# LENS tech_stack

## SUMMARY
LENS = tech stack / Android platform / calendar / build+distribution on Windows.

RECOMMENDED STACK: native Kotlin + Jetpack Compose (Material 3), single-module-per-concern Gradle project, built headless on Windows with JDK 21 + Android SDK cmdline-tools (no Android Studio), installed to phone via adb-over-Wi-Fi. Local-first: Room 2.8.5 = source of truth, custom outbox sync -> Supabase (supabase-kt 3.8.0 postgrest+auth, Postgrest defaultSchema = new schema e.g. `fitness`). All recommendation logic lives in pure-Kotlin JVM module `:algo` (no Android deps) -> JUnit5/kotest-property golden + property tests and a seeded simulation/replay CLI run in seconds with only a JDK. Tunable constants shipped as versioned JSON from Supabase (params-as-data = OTA tuning without reinstall); every recommendation logged with algo_version + params_version + input hash + decision trace for later Claude review.
Calendar: Android CalendarContract (READ_CALENDAR only, Instances table expands recurrences, reads every calendar synced on phone incl. Google primary) + deterministic event classifier (handles Dutch titles 'Gym — sessie C', Basic-Fit location, rejects stale all-day Todoist 'Gym' tasks). Google Calendar REST rejected: OAuth testing-mode refresh tokens die after 7 days, calendar scopes sensitive -> verification. Write-back optional later via ACTION_INSERT intent (no permission) or direct insert.
Rest timer: timestamp-based state (survives process death) + AlarmManager.setAlarmClock (exact, Doze-exempt, never deferred) + ongoing notification with native chronometer countdown (Android 16 Live Update promotion) + foreground service type `health` during active session; log alarm latency to verify. Keep-screen-on optional toggle.
Auth: email+password in shared project auth (reuse existing account if any), session persisted+auto-refreshed by supabase-kt; RLS user_id = (select auth.uid()) on every table, grants only to authenticated (never anon). Custom schema must be added to Data API 'Exposed schemas' (append, don't replace — chess app shares project) + explicit GRANTs.
Health Connect: worth it in phase 2 (read body weight + running sessions + optional sleep; write strength ExerciseSessionRecord). Widget (Glance) / Wear OS: phase 3, optional.
RUNNER-UP: Expo SDK 57 (RN 0.86, TS) + expo-sqlite/Drizzle + supabase-js (db.schema) + expo-calendar + custom Expo Module in Kotlin for timer/FGS. Wins on OTA (expo-updates) and web preview, loses on native timer/notification/Health Connect integration (needs Kotlin anyway), UI nativeness, dependency churn. Flutter third: no advantage for Android-only app, toolchain not installed.

### Calendar access: CalendarContract vs Google Calendar REST [engineering-fact]
CalendarContract: READ_CALENDAR runtime perm only, no Google Cloud project/OAuth; reads every calendar account synced to phone (Google primary, subscribed/ICS e.g. Todoist if sync enabled). Instances table returns per-occurrence begin/end for recurring events in a window (Instances.CONTENT_URI + begin/end). Calendars identified by ACCOUNT_NAME+ACCOUNT_TYPE (com.google); ACCOUNT_TYPE_LOCAL = device-only. Insert requires CALENDAR_ID, DTSTART (UTC ms), EVENT_TIMEZONE, DTEND (non-recurring) — inserted events into a Google calendar sync up via Android sync adapter. Intent ACTION_INSERT on Events.CONTENT_URI adds event via Calendar app with NO permission. Google REST: external app in 'Testing' => refresh token expires after 7 days (except openid/email/profile only); calendar.readonly / calendar.events.readonly are sensitive scopes -> verification to publish. => CalendarContract clearly better for personal Android app.
SRC: https://developer.android.com/guide/topics/providers/calendar-provider | https://developers.google.com/identity/protocols/oauth2 (refresh token expiration) | https://developers.google.com/calendar/api/auth

### Floating-point determinism JVM vs ART [engineering-fact]
Java 17+ restored always-strict IEEE-754 semantics for +,-,*,/ (JEP 306). java.lang.Math transcendental fns (exp, log, pow) may differ by ~1 ulp between implementations/intrinsics; java.lang.StrictMath is bit-exact (fdlibm). JVM unit tests vs on-device ART could therefore diverge in last bits unless algo uses StrictMath + final rounding to loadable increments. Same issue in JS (V8 vs Hermes Math.*).
SRC: https://openjdk.org/jeps/306 | https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Math.html

### RIR self-report error (input for simulation noise model) [moderate]
Lifters' prediction of reps-to-failure is imperfect: meta-analysis found average underprediction ~1 rep (≈0.95), better accuracy closer to failure and in later sets. Use σ≈1 rep noise in synthetic athlete model.
SRC: Halperin I, et al. 2022, Sports Med 52:377-390 'Accuracy in Predicting Repetitions to Task Failure in Resistance Exercise: A Scoping Review and Exploratory Meta-analysis'

## ALGORITHMS
### CalendarGymEventClassifier v1
PURPOSE: Turn phone calendar events of a week into PlannedGymSession list (date, time, session type / challenge session code), rejecting non-gym and stale all-day Todoist tasks; deterministic and explainable.
IN: CalendarContract.Instances rows for window [weekStart, weekStart+7d) where weekStart = Monday 00:00 Europe/Amsterdam (ISO-8601 week, ZoneId injected): instanceBegin/End (UTC ms), eventId, calendarId, title, description, eventLocation, allDay, status, selfAttendeeStatus. User settings: selectedCalendarIds (default = visible com.google calendars, excluding names matching /todoist/i), gymLocationKeywords (default ["basic-fit","basicfit","ierse pond"]), per-instance overrides table (eventId+beginUtc -> isGym/type). Enrolled challenges' session alias regexes (from challenge template data). Exercise catalog names+aliases (EN+NL).
OUT: List<PlannedGymSession{localDate, startLocal, endLocal, type ∈ {CHALLENGE(code), PUSH, PULL, LEGS, UPPER, LOWER, FULL, COMBO(set), UNSPECIFIED}, sourceEventId, score, features[]}> + ClassificationTrace per event.
PSEUDO:
norm(s) = lowercase(NFKD(s) minus combining marks), collapse whitespace, '—'/'–' -> '-'
GYM_KW  = /\b(gym|sportschool|fitness|krachttraining|workout|training|basic[- ]?fit)\b/
NEG_KW  = /\b(hardlopen|hardloop|run|running|schaak|chess|zwemmen|swim)\b/
SPLIT = {PUSH:/\b(push|duw|borst|chest|shoulders?|schouders?|triceps)\b/, PULL:/\b(pull|trek|rug|back|biceps|optrek\w*|pull-?ups?)\b/, LEGS:/\b(legs?|benen|been|squat|leg day)\b/, UPPER:/\b(upper|bovenlichaam)\b/, LOWER:/\b(lower|onderlichaam)\b/, FULL:/\b(full ?body|volledig)\b/}
for inst in instances sorted by (beginUtc, eventId):
  if inst.calendarId ∉ selected or inst.status==CANCELED or inst.selfAttendeeStatus==DECLINED: continue
  if override(inst.eventId, inst.beginUtc) exists: emit override; continue
  t=norm(title); d=norm(description); l=norm(location); f=[]; s=0
  if GYM_KW.find(t): s+=W_TITLE; f+='title_kw'
  if any(k in l for k in gymLocationKeywords): s+=W_LOC; f+='location'
  if countDistinctCatalogNames(d) >= 2: s+=W_DESC; f+='desc_exercises'
  if inst.allDay: s+=W_ALLDAY; f+='all_day'
  dur=(end-begin)/60000; if DUR_MIN<=dur<=DUR_MAX: s+=W_DUR_OK else s+=W_DUR_BAD
  if NEG_KW.find(t): s+=W_NEG; f+='neg_kw'
  if s < THRESH: trace(reject); continue
  type = firstMatch(enrolledChallenges sorted by enrollmentId, alias regex on t)  // e.g. /sessie\s*([abc])\b/ -> code, /test\s*-?dag|test day/ -> TEST
      ?: (m = {k | SPLIT[k].find(t+' '+d)}; if |m∩{PUSH,PULL,LEGS}|>=2 -> COMBO(m) elif |m|==1 -> m.single elif m non-empty -> first by fixed order [FULL,UPPER,LOWER,PUSH,PULL,LEGS] else UNSPECIFIED)
  emit PlannedGymSession(localDate(begin, zone), ..., type, score=s, features=f)
dedupe per localDate: overlapping intervals -> keep max score, tie -> earliest begin, tie -> smallest eventId
weekPlan = planned ∪ recommended(days without planned)  // recommender owned by training-algo module
worked examples: 'Gym — sessie C (volume en techniek)' 19:45-21:15 @Basic-Fit, desc lists exercises -> 3+3+1+1=8 accept, CHALLENGE(C); Todoist all-day 'Gym' -> 3-4-1=-2 reject; 'Training chess' -> 3+1-5=-1 reject.
refresh triggers: app foreground, ContentObserver on CalendarContract.Instances/Events (debounce 2000 ms), daily WorkManager at 05:00 local.
CONST: W_TITLE=+3, W_LOC=+3, W_DESC=+1, W_ALLDAY=-4, W_DUR_OK=+1, W_DUR_BAD=-1, W_NEG=-5, THRESH=3, DUR_MIN=30 min, DUR_MAX=180 min, debounce 2000 ms. Rationale: either title keyword or gym location alone (3) suffices; all-day penalty kills stale Todoist tasks even when titled 'Gym'; NEG_KW prevents 'Hardlopen'/chess collisions. Tune with logged corrections.
LOG: calendar_classification_log: classifier_version, week_start, sha256(calendarId|eventId|beginUtc), normalized title, features[], score, decision, mapped type; user_correction rows (user marks 'not gym' / changes type / adds session not in calendar) -> precision/recall per feature; planned-vs-actual (did a logged session occur same day ±1) -> calendar adherence stats.

### RestTimerScheduler v1
PURPOSE: Reliable, overridable rest timer after each set that survives process death, Doze, screen lock; logs prescribed vs actual rest for the progression algorithm.
IN: setCompleted event (setLogId, exerciseId, completedAtWall), prescribedRestSec from training algorithm, user adjustments (+/-15 s, skip, custom), next-set-start event, SystemClock.elapsedRealtime(), System.currentTimeMillis(), Settings.Global.BOOT_COUNT, AlarmManager.canScheduleExactAlarms(), user setting strictTimer (default true), keepScreenOn setting.
OUT: Persisted RestTimer row, scheduled alarm, ongoing countdown notification (Live Update on Android 16+), 'Rest done' alert (vibration/sound), rest_event log row.
PSEUDO:
onSetCompleted(set):
  d = clamp(prescribedRestSec, MIN_REST, MAX_REST)
  timer = RestTimer(id=uuidv7(), setId, prescribed=d, startWall=nowWall, startElapsed=nowElapsed, boot=BOOT_COUNT, endWall=nowWall+d*1000, adj=[], endedBy=null)
  dao.insert(timer)                      // before UI update; state = timestamps, never a counter
  schedule(timer); postOngoing(timer)    // chronometer countdown to endWall, actions [-15s, +15s, Skip], setOnlyAlertOnce
remainingMs(timer) = if timer.boot==BOOT_COUNT: timer.startElapsed + (timer.endWall-timer.startWall) - nowElapsed else timer.endWall - nowWall
onAdjust(delta): newEnd = max(nowWall+MIN_LEFT_MS, timer.endWall+delta*1000); newEnd = min(newEnd, timer.startWall+MAX_REST*1000); timer.adj += (nowWall, delta); timer.endWall=newEnd; persist; reschedule; repost
onSkip(): cancelAlarm; timer.endedBy=SKIP; endedAt=nowWall; persist; cancel ongoing
schedule(timer):
  if canScheduleExactAlarms():
     if strictTimer: setAlarmClock(AlarmClockInfo(endWall, openSessionPI), firePI)
     else setExactAndAllowWhileIdle(RTC_WAKEUP, endWall, firePI)
  else: setAndAllowWhileIdle(RTC_WAKEUP, endWall, firePI); timer.precise=false; show banner 'enable exact alarms'
onFire(firedAtWall):
  latency = firedAtWall - timer.endWall; log
  if app foreground: in-app haptic + optional tone; else post channel 'rest_done' (IMPORTANCE_HIGH, vibration VIB_PATTERN, autoCancel)
  ongoing notification -> 'Next: <exercise> set k/n · <load> × <reps>'; timer.endedBy=ELAPSED
onNextSetStarted(set2): actualRestSec = (set2.startedAtWall - set.completedAtWall)/1000; write rest_event
session lifecycle: Start session -> startForeground(type=health if ACTIVITY_RECOGNITION granted else specialUse); Finish/abandon -> stopForeground + cancel alarms; app start -> reconcile: any timer with endedBy==null and endWall<now -> mark ELAPSED_WHILE_DEAD; endWall>now -> reschedule.
keepScreenOn: if setting==ALWAYS -> window FLAG_KEEP_SCREEN_ON during session; if DURING_REST -> only while remainingMs>0.
CONST: MIN_REST=15 s, MAX_REST=900 s (OAP heavy sets 3-5 min fit), MIN_LEFT_MS=5000, adjust step=15 s (long-press 60 s), VIB_PATTERN=[0,350,150,350,150,350] ms, pre-alert at T-10 s only when app/FGS foreground (in-app haptic, no alarm), channels: 'session_ongoing' IMPORTANCE_LOW silent, 'rest_done' IMPORTANCE_HIGH. strictTimer default true (setAlarmClock: exact, Doze-exempt; side effect: alarm icon/next-alarm shown during rest). Switch default to setExactAndAllowWhileIdle if user dislikes icon and logged p95 latency <= 2 s.
LOG: rest_event: session_id, set_log_id, exercise_id, prescribed_s, adjustments[(t,delta)], ended_by {ELAPSED,SKIP,NEXT_SET_EARLY,ELAPSED_WHILE_DEAD}, actual_rest_s, alarm_mode, alarm_latency_ms, app_state_at_fire {foreground,background,dead}, rest_algo_version. Feeds: rest-time recommender (users systematically extending/skipping), rep-drop vs actual rest for progression model, reliability monitoring (latency p95 per Android version/OEM).

### OutboxSync v1 (Room <-> Supabase custom schema)
PURPOSE: Local-first persistence with deterministic, idempotent sync for a single user (possibly 2 devices), robust to offline gym, paused Supabase project and app kills.
IN: Room tables split into: (A) append-only immutable logs (set_log, override_event, rest_event, recommendation_log, calendar_classification_log, session_event); (B) mutable user entities (session, session_exercise, exercise_rating, preferences, muscle_goal, challenge_enrollment, algo_params selection) with columns id (UUIDv7 client), updated_at (client wall ms), deleted_at nullable, device_id, server_updated_at (server-set); (C) read-only curated data (exercise catalog, muscles, challenge templates, algo_params versions) with version column. Outbox table: (seq autoinc, table, row_id, op {UPSERT,INSERT_IGNORE}, payload_json, enqueued_at, attempts). Supabase JWT session.
OUT: Server rows in schema `fitness`; pulled rows merged into Room; sync_run log.
PSEUDO:
localWrite(row): in one Room transaction: write row (B: updated_at=nowWall, device_id) + outbox.append(table,row.id,op,payload)
push(): while batch = outbox.oldest(BATCH):
  group by table; for A: POST upsert with on_conflict=id, Prefer: resolution=ignore-duplicates; for B: RPC fitness.lww_upsert(table, rows) which does INSERT ... ON CONFLICT(id) DO UPDATE SET ... WHERE excluded.updated_at > t.updated_at OR (excluded.updated_at = t.updated_at AND excluded.device_id > t.device_id)
  on 2xx: delete those outbox seqs; on 401: refresh session once, retry; on 5xx/network/paused: attempts++, schedule retry at BACKOFF_BASE*2^min(attempts,10) capped BACKOFF_CAP; on 4xx other: move to dead_letter (kept locally, surfaced in debug screen)
pull(table): cursor = sync_cursor[table] (server_updated_at, id); fetch rows where server_updated_at >= cursor.ts - OVERLAP order by server_updated_at, id limit PAGE; for each: if local row has pending outbox entry -> apply LWW rule (same as server); else overwrite; advance cursor to last (ts,id); repeat until page < PAGE
syncAll(): push() then pull(B tables, C tables) ; A tables pull only on new-device bootstrap (full download)
triggers: session finish, app foreground, WorkManager OneTime with NetworkType.CONNECTED on any enqueue (KEEP policy), periodic every PERIODIC.
server side: trigger sets server_updated_at = now() on insert/update; RLS user_id = (select auth.uid()); user_id default auth.uid(); deletes are soft (deleted_at), hard purge by pg_cron after 90 d only for B tables.
UUIDv7 = 48-bit unix ms ‖ ver 7 ‖ 74 random bits (SecureRandom); clock+random injected in tests.
CONST: BATCH=200 rows, PAGE=500, OVERLAP=2000 ms, BACKOFF_BASE=30 s, BACKOFF_CAP=6 h, PERIODIC=6 h (WorkManager min 15 min), dead-letter after 4xx immediately (schema/RLS errors are not transient). LWW tiebreak = device_id lexical (deterministic).
LOG: sync_run: started_at, trigger, pushed_count per table, pulled_count, duration_ms, http errors, outbox_depth_before/after, max outbox age; dead_letter rows. Used to detect paused project, RLS/grant mistakes, clock skew (client updated_at vs server_updated_at delta).

### DeterministicEngine contract + versioning + decision trace
PURPOSE: Guarantee every recommendation (session type today, weekly plan, exercise selection, sets/reps/load, rest) is a pure, reproducible function of logged inputs + versioned params, so Claude Code can later replay history and compare algorithm versions.
IN: EngineInput (immutable data class): today LocalDate, zone, nowWall, user prefs, muscle goals, ratings, catalog snapshot version, training history slice, enrolled challenges + template version, calendar plan, bodyweight; Params JSON (version id) from fitness.algo_params (pulled, cached, pinned per session); engine code version ALGO_VERSION (semver constant compiled in :algo).
OUT: Recommendation + DecisionTrace {ruleId, inputsUsed, candidateScores[], chosen, warnings[] e.g. 'preference 2x12 overridden: reason R, citation C'} + hashes.
PSEUDO:
canonical(x) = JSON with sorted keys, numbers as fixed decimal strings (loads 0.01 kg, time ms), lists in deterministic order
inputHash = sha256(canonical(EngineInput)); paramsHash = sha256(canonical(Params))
rec, trace = Engine[ALGO_VERSION].run(input, params)   // no clock/random/IO/locale inside; no HashMap iteration (use sorted lists/TreeMap); all ties broken by (score desc, stableId asc); transcendental math via StrictMath; final loads rounded to equipment increments (e.g. 2.5 kg plates, machine step 5 lb = 2.268 kg, assisted machine negative load)
persist recommendation_log(id, ALGO_VERSION, params_version, inputHash, paramsHash, outputHash=sha256(canonical(rec)), trace_json, context {screen, sessionId})
params update flow: Claude review -> new row algo_params(version, json, created_at, notes) -> app pulls, activates at next session start (never mid-session) -> logged
replay(versionB): for each logged recommendation: rebuild EngineInput from snapshot (store full canonical input JSON compressed for first year; ~KBs/session) -> run B -> diff report (load deltas, exercise swaps, warnings) -> markdown/CSV for Claude.
CONST: Hash = SHA-256 hex. Canonical numeric precision: load 0.01 kg, duration 1 ms, ratios 1e-4. Params activation: next session start. Input snapshot retention: 365 d full JSON, then hashes only (decide later).
LOG: recommendation_log (all fields above) + user response per recommendation: accepted / overridden (field, old, new, reason enum e.g. too_easy, too_hard, feeling_good, feeling_bad, no_time, equipment_busy, pain, other) / skipped; outcome (actual reps, RIR per set). Acceptance rate and override reasons per rule id = primary tuning signal.

### SimulationHarness v1 (synthetic athletes + golden tests)
PURPOSE: Fast offline regression testing of the deterministic algorithms over long synthetic histories, and counterfactual replay of real logs; runs on JVM in seconds (`gradlew :sim:run`).
IN: Persona definitions (JSON): starting e1RM per exercise, personal rep-curve slope, recovery, adherence, preferences/goals (e.g. 'OAP user 70.7 kg, 3x8-10', 'friend 2x12', 'legs-only', 'no-legs', 'pull-focus maintain push+legs'); seed list; horizon; engine version + params.
OUT: Per persona/seed: time series CSV (load, reps, RIR, e1RM true vs estimated), metrics JSON, invariant-violation list; golden snapshot files.
PSEUDO:
rng = SplittableRandom(seed)   // deterministic
for week in 1..H: for day in plan(engine):
  if rng.nextDouble() > adherence: mark missed; continue
  rec = engine.run(stateToInput(state), params)
  for each set: trueRepsMax = floor((e1RM_true/load - 1)/k_persona)  // Epley-form inverse; k_persona < 1/30 for flatter curve (user's 18 BW reps vs table 13)
     reps = min(rec.reps, trueRepsMax); trueRIR = trueRepsMax - reps; reportedRIR = clamp(round(trueRIR + N(0, SIGMA_RIR)), 0, 5)
     fatigue: trueRepsMax_next_set -= SET_DROP
  adaptation: e1RM_true += G * stimulus(sets within RIR<=3) * (1 - e1RM_true/CAP) - DETRAIN*(missed days>10)
  occasionally inject overrides (P_OVERRIDE) with reasons, skips, equipment busy
metrics: weeks to reach target RIR band, # sessions with reported RIR 0 when target >=2 (overshoot), load oscillation count (sign changes of Δload over 4 sessions), plateau->deload detection lag, muscle coverage per goal (sets/week vs target), disliked-exercise usage only when sole coverage
invariants (must be 0 violations): same input -> identical output bytes; Δload per session within [-15%, +10%]; never prescribe load not loadable on equipment; 'no_time'/'equipment_busy' overrides never change progression state; 'do not train' muscle groups get 0 direct sets; challenge-occupied days not double-booked
golden tests: fixtures/golden/<case>.json {input, expected rec, expected trace}; `-PupdateGoldens` rewrites; diffs reviewed in git.
CONST: SIGMA_RIR=1.0 rep (Halperin 2022 ~0.95 rep mean error), seeds 1..200, H=52 weeks, k_default=1/30 (Epley), SET_DROP=1 rep/set at RIR<=2 (assumption, tune), G=0.004 per effective set, CAP=1.4*start e1RM, DETRAIN=0.5%/week after 10 missed days, P_OVERRIDE=0.1. All model constants are assumptions -> replace with values fitted from user logs after ~8 weeks.
LOG: Uses real logs to fit persona: per exercise rep curve (reps vs %e1RM pairs), RIR report vs subsequent performance, adherence rate, override frequency/reasons. Output sim_report stored as artifact for Claude review cycles; no DB writes needed.

## RISKS
- Exposed-schemas setting is project-wide: replacing instead of appending the list (public, graphql_public, assistant, …) would break the chess app — read current value first, user applies in Dashboard > Data API.
- Shared auth + health data in same project as chess app with 6 users: any table missing RLS or granting anon leaks data — enforce RLS-on check in migration tests and Supabase advisors.
- Free-plan auto-pause after 7 days low activity (if project is Free): sync stops until manual restore; offline-first mitigates, app must surface 'sync paused' state.
- supabase-kt is community-maintained (bus factor); built with Kotlin 2.3.21/Ktor 3.4.3 vs app Kotlin 2.4.20 — usually forward-compatible, but keep Ktor/serialization aligned; isolate behind repository interface so raw Ktor PostgREST calls can replace it.
- Exact alarms not pre-granted on Android 14+ for SCHEDULE_EXACT_ALARM; OEM battery killers (Samsung/Xiaomi/OnePlus) may still delay/kill — need battery-optimization exemption prompt, latency logging, on-device Doze test (`adb shell dumpsys deviceidle force-idle`).
- FGS type health requires a runtime permission (ACTIVITY_RECOGNITION) granted before startForeground, else SecurityException on Android 14+ — fallback to specialUse.
- Signing key loss or debug-key change forces uninstall => local DB wiped incl. unsynced logs. Back up keystore; block reinstall until outbox empty.
- Material 3 Expressive only in 1.5.0 alpha (MaterialExpressiveTheme experimental) — API churn if adopted now.
- JDK 25 as Gradle daemon may hit untested AGP paths — pin JDK 21 via daemon JVM criteria.
- Android SDK license acceptance and phone developer-options/wireless-debugging are user actions; emulator needs Windows Hypervisor Platform (system setting) — user decision.
- Calendar classification errors: Dutch titles, shifting days, stale Todoist all-day tasks, other 'training' events — need user-correctable overrides + logging; DST change 25 Oct 2026 (Europe/Amsterdam) must not shift week boundaries (use java.time with zone).
- Floating-point/library nondeterminism (Math vs StrictMath, HashMap order, locale formatting, System clock inside algo) would make replays differ from on-device decisions — enforce contract via lint/test (forbidden imports in :algo).
- Developer verification goes global '2027 and beyond' — sideload path may need limited-distribution account; ADB installs reportedly remain possible.
- No OTA for Kotlin code: logic bugs found in gym need PC + adb (or CI + Obtainium); mitigate with params-as-data and feature flags.
- PowerSync docs reference Room 3.0 for its integration while Room stable is 2.8.5 — another reason to avoid it now.
- Assisted pull-up machine uses lb (5-lb pin steps) while plates/dumbbells are kg — unit/increment model per equipment needed in data model, else wrong rounding.
